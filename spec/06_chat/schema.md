# 06 Chat — Database Schema

> AI Chatbot uses both MySQL (query execution logs) and MongoDB (chat history, activity logs).

---

## MySQL — ai_query_logs

SQL audit trail for every AI query.

```sql
CREATE TABLE ai_query_logs (
  id            VARCHAR(36)   PRIMARY KEY,
  user_id       VARCHAR(36)   NOT NULL,
  question      TEXT          NOT NULL,
  generated_sql TEXT          NOT NULL,
  result_count  INT           DEFAULT 0,
  execution_time_ms INT      DEFAULT 0,
  created_at    TIMESTAMP     DEFAULT CURRENT_TIMESTAMP,

  INDEX idx_ai_query_user (user_id),
  INDEX idx_ai_query_created (created_at)
);
```

| Field | Type | Description |
|-------|------|-------------|
| id | VARCHAR(36) | UUID primary key |
| user_id | VARCHAR(36) | FK → users.id |
| question | TEXT | Original user question (Thai/English) |
| generated_sql | TEXT | SQL generated by LLM |
| result_count | INT | Number of rows returned |
| execution_time_ms | INT | Query execution time in milliseconds |
| created_at | TIMESTAMP | When query was executed |

### Indexes
- `idx_ai_query_user` on `user_id` — filter by user
- `idx_ai_query_created` on `created_at` — chronological queries

## MongoDB — chat_messages

Collection for chat message history. Schema-flexible — each message can have different metadata.

```
Collection: chat_messages
Database:   versus_erp
```

```js
{
  _id: ObjectId,
  userId: ObjectId,         // ref → users
  sessionId: "uuid",        // chat session grouping
  question: "วันนี้ยอดขายเท่าไหร่",
  answer: "วันนี้ยอดขาย 85,000 บาท จาก 6 คัน",
  generatedSql: "SELECT SUM(grand_total) FROM invoices WHERE DATE(created_at) = CURDATE()",
  format: "text",           // text | csv | html | json | table
  resultRowCount: 6,
  executionTimeMs: 230,
  toolCalls: [              // present if harness mode
    {
      toolName: "sql_query",
      arguments: { "query": "SELECT ..." },
      result: { type: "table", data: [...] },
      status: "done",
      startedAt: ISODate(...),
      completedAt: ISODate(...)
    }
  ],
  createdAt: ISODate("2026-07-18T10:30:00+07:00")
}
```

| Field | Type | Description |
|-------|------|-------------|
| _id | ObjectId | Auto-generated |
| userId | ObjectId | ref → users collection |
| sessionId | UUID | Groups messages into chat sessions |
| question | string | Original user input |
| answer | string | Formatted AI response |
| generatedSql | string | SQL used to fetch data |
| format | string | Output format: text, csv, html, json, table |
| resultRowCount | number | Rows in result set |
| executionTimeMs | number | Total processing time |
| toolCalls | array | Tool calls if agent/harness mode |
| createdAt | Date | Message timestamp |

### Indexes

```js
// Create indexes on application startup
db.chat_messages.createIndex({ sessionId: 1, createdAt: -1 });
db.chat_messages.createIndex({ userId: 1, createdAt: -1 });
db.chat_messages.createIndex({ createdAt: -1 }, { expireAfterSeconds: 7776000 }); // TTL: 90 days
```

| Index | Fields | Purpose |
|-------|--------|---------|
| `idx_session_time` | `sessionId: 1, createdAt: -1` | Load chat history for a session (sorted newest-first) |
| `idx_user_time` | `userId: 1, createdAt: -1` | Get recent messages by user |
| `ttl_cleanup` | `createdAt: -1` | Auto-delete messages older than 90 days |

## MongoDB — activity_logs

Append-only audit trail for all system actions.

```
Collection: activity_logs
Database:   versus_erp
```

```js
{
  _id: ObjectId,
  userId: ObjectId,               // who did it
  action: "invoice.create",       // action identifier
  entityType: "invoice",          // target entity
  entityId: "uuid",               // target entity ID
  changes: {
    from: { status: "DRAFT" },     // previous state
    to: { status: "CONFIRMED" }    // new state
  },
  metadata: {                      // extra context
    ipAddress: "127.0.0.1",
    userAgent: "Mozilla/5.0 ..."
  },
  createdAt: ISODate("2026-07-18T10:30:00+07:00")
}
```

| Field | Type | Description |
|-------|------|-------------|
| _id | ObjectId | Auto-generated |
| userId | ObjectId | Actor who performed action |
| action | string | Action identifier (dot-notation) |
| entityType | string | Entity affected |
| entityId | string | ID of affected entity |
| changes | object | Before/after diff of changes |
| metadata | object | Extra context (IP, user agent) |
| createdAt | Date | When action occurred |

### Indexes

```js
db.activity_logs.createIndex({ userId: 1, createdAt: -1 });
db.activity_logs.createIndex({ entityType: 1, entityId: 1 });
db.activity_logs.createIndex({ action: 1, createdAt: -1 });
db.activity_logs.createIndex({ createdAt: -1 }, { expireAfterSeconds: 15552000 }); // TTL: 180 days
```

| Index | Fields | Purpose |
|-------|--------|---------|
| `idx_user_activity` | `userId: 1, createdAt: -1` | Recent activity by user |
| `idx_entity` | `entityType: 1, entityId: 1` | Activity history for specific record |
| `idx_action_time` | `action: 1, createdAt: -1` | Filter by action type |
| `ttl_cleanup` | `createdAt: -1` | Auto-delete logs older than 180 days |

### Action Naming Convention

```
{entity}.{verb}

invoice.create
invoice.update
invoice.delete
job.status_change
product.stock_adjust
customer.create
user.login
user.logout
chat.query
```

## Redis Cache Keys

Used for caching AI responses, rate limiting, and session management.

| Key Pattern | Type | TTL | Description |
|-------------|------|-----|-------------|
| `ai:cache:{md5(question)}` | String (JSON) | 10 min | Cached LLM response — same question returns instantly |
| `ai:job:{jobId}` | String (JSON) | 30 min | Async job result for heavy queries |
| `ratelimit:{userId}:chat` | Counter | 1 min | Rate limit: 20 requests/min/user |
| `session:{sessionId}` | Hash | 24 hr | User session data |

## RabbitMQ Queues

| Queue Name | Type | Producer | Consumer | Description |
|------------|------|----------|----------|-------------|
| `erp.ai.expensive_query` | Durable | ChatService | aiWorker.ts | Heavy queries offloaded from main request |
| `erp.audit.log` | Durable | Any module | auditWorker.ts | Activity log → MongoDB (fire-and-forget) |
| `erp.notifications.send` | Durable | Any worker | notificationWorker.ts | Notify user when async job completes |
